## 2. 产品范围

手表负责：查看露台缩略快照、快速知道发生什么、确认已读、查看一条计划、留一句反馈。手机负责：看完整画面、编辑计划时间、管理长期记忆、对讲与设备设置。

| 功能 | S9 首期 | 手机 |
| --- | --- | --- |
| 此刻 | 缩略快照、拍摄时间、同步状态、摘要 | 视频、完整证据与设备详情 |
| 提醒 | 查看摘要、确认已读 | 纠正识别、关联计划/记忆 |
| 计划 | 只读内容与时间 | 新增、修改、结束和恢复 |
| 反馈 | 听写、核对、提交反馈 | 把反馈转为计划/记忆草稿并确认 |
| 对讲、直播 | 首期不做 | 待 SDK 能力验证后接入 |
| 表盘复杂功能 | 后续扩展 | 不阻塞主路径 |

已读不代表认可 AI 判断；保存反馈不代表已经更新计划、记忆或训练模型。不得用通用确认按钮触发设备动作。

## 3. 视觉与尺寸

沿用白底、淡紫卡片、深紫主按钮，删除霓虹和持续闪烁。watchOS 深色/Always-On 模式另提供低亮度方案；白色原型用于风格对齐，不表示 Always-On 也保持白底。

| 机型 | 设计画布 | 物理像素参考 |
| --- | --- | --- |
| S9 41mm | 176×215 pt | 352×430 |
| S9 45mm | 198×242 pt | 396×484 |

尺寸用于原型画布，实施时用 Xcode 对应模拟器和实际安全区验证。参考入口：[Apple 技术规格](https://support.apple.com/en-us/111833)、[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/designing-for-watchos)。本轮未重新在线核验系统版本兼容表。

- 原生使用 SwiftUI 系统导航与 ScrollView，支持数码表冠滚动；不要把 HTML 当原生 UI 嵌入。
- 主操作整行可点，首期以至少 44pt 触控高度为设计目标，实机验证舒适性。
- 文字可换行；长内容滚动查看，不压缩到不可读。每页一个主动作。
- 中文为主，小屏不强制双语并排；系统时间由 watchOS 提供，不复刻 HTML 的固定 09:41。
- 支持 Dynamic Type、VoiceOver、减少动态效果；状态同时提供文字，不只靠紫色深浅。
- 页面转场优先系统动画；真实提交成功才触发完成触感，待同步不使用成功触感。

## 4. 页面与状态机

### 此刻

显示摘要快照和更新时间，入口为露台变化、今天计划、告诉 Homi。

状态：loading / fresh / stale / empty / error。同步中断时保留最后快照并注明时间；不能把手机不可达等同于摄像头离线。分别维护 watch↔phone 同步状态和 device↔service 连接状态。

### 提醒详情

打开提醒 → 展示发生时间和简短事实/不确定判断 → 我知道了 → 服务端确认已读。

无网则显示已在本机标记、待同步，恢复后提交。事件不存在或已失效时提示并回到列表，不能跳到另一条事件。查看画面通过明确的手机继续入口。

### 计划详情

只读展示计划和时间；expired / ended / scheduled / active 状态来自服务端。手表不直接改 enabled。修改操作移交 iPhone 同一 planId。

### 反馈

开始系统听写 → 用户核对并可重试/编辑 → 确认提交 → submitting → saved / queued / failed。

听写权限拒绝或不可用时允许转到手机；小尺寸输入能力依系统而定，不保证提供完整屏幕键盘。HTML 文本框只是方便演示。

取消不创建反馈。提交超时先查询结果或以同一幂等键重试，不能生成重复反馈。切后台或抬腕结束不自动提交。

### 在 iPhone 继续

移交上下文只含资源类型和 ID。手机可达时传递请求；不可达时保留待处理上下文，提示用户手动打开手机。不能保证系统允许远程强制启动手机 App，不把传递成功说成手机已打开。

## 5. 工程与同步方案

建议首期采用 iPhone companion：SwiftUI watchOS App + 配套 iOS App + 现有业务后端。

1. iPhone 登录并获取家庭权限、设备/计划/提醒快照。
2. iPhone 用 WCSession.updateApplicationContext 发送最新紧凑快照；该通道适合最新状态，不用于要求每条必达的命令。
3. 两端激活 WCSession 并记录配对/安装/可达状态。实时请求可用 sendMessage，但必须处理不可达与错误回调。
4. 离线操作写入手表持久 outbox；transferUserInfo 可作为后台传递通道，不能承诺立即送达。
5. iPhone 收到命令后调用后端，获得业务成功结果再回传 ack。传输成功不是业务成功。
6. 手表按 commandId 删除已确认 outbox；应用重启仍保留未确认项。

参考：[WatchConnectivity](https://developer.apple.com/documentation/watchconnectivity)。独立联网 watchOS App 可后续评估，本期不同时建设两套鉴权和同步架构。不能假定蓝牙后台常在线。

## 6. 消息与接口契约（建议，尚未实现）

所有消息带 schemaVersion、messageId、householdId、sentAt；时间使用带时区的 ISO 8601，服务端存 UTC。

| 类型 | 字段 | 语义 |
| --- | --- | --- |
| Snapshot | revision、generatedAt、deviceStatus、eventSummaries、plans | 最新快照；列表限量并截短摘要，不传大图/视频 |
| Command | commandId、type、targetId?、payload、baseVersion?、createdAt | markRead / submitFeedback / continueOnPhone |
| Ack | commandId、status、serverId?、serverVersion?、errorCode? | succeeded / failed；只在后端确认后成功 |
| ContinueContext | resourceType、resourceId、expiresAt | 手机定位同一记录，须重新校验权限 |

后端在手机端契约上增加：

| 接口 | 用途 |
| --- | --- |
| GET /api/v1/watch/snapshot | 聚合家庭/设备摘要、计划和最新提醒，返回 revision |
| POST /api/v1/events/{id}/read | 当前用户标记已读；不等于反馈同意 |
| POST /api/v1/feedback | 保存普通原话反馈，区别于仅针对 analysis 的反馈接口 |
| GET /api/v1/commands/{commandId} | 查询超时提交最终结果 |

写入使用 commandId 作为幂等键。同键同内容返回原结果，同键不同内容拒绝。服务端校验账号与家庭权限，不能信任手表发送的 householdId。

Snapshot 聚合 event、analysis 的映射需后端冻结：AI 摘要关联 evidenceId；原始设备事件不一定已经分析，不允许一概写成 AI 已完成。

## 7. 离线、一致性与错误

- outbox 状态 pending / sending / succeeded / failed；重试采用有上限退避，不持续唤醒手表。
- 401：手机重新登录后再同步；403：终止重试并清除不可访问缓存；409：提示状态已更新，重新取快照。
- 429/503：按服务端建议退避；永久性输入错误保留原文并允许用户修改/取消。
- 重复、乱序快照按 revision 处理；更旧快照不能覆盖新状态。
- 切换家庭、退出账号、解除配对时清理相关缓存/outbox，不把旧账号命令发送给新账号。
- 每次用户确认生成稳定 commandId，重复回调不重复写入。
- 原型的“恢复同步”仅模拟成功；正式版恢复网络后也必须等待业务 ack。

## 8. 语音与隐私

优先系统听写/文本输入能力，先在 S9 对应 watchOS 版本验证中文支持和输入体验。若改用自录音＋ASR，需另行确定权限、格式、时长、传输、取消和删除规则，不默认为系统能力。

不在手表放模型 Key 或设备长期 Token。尽量同步文本摘要而非家庭画面；锁屏通知默认克制摘要，用户点击后查看详情。音频上传与保留需告知用户，日志不记录音频、令牌及完整私密反馈。

## 11. 缩略画面增补规格（2026-10-15）

### 页面与交互

- 首页加入露台缩略图按钮，点开“露台快照”。详情以完整图片比例展示，附拍摄时间、刷新按钮和转手机入口。
- 首页可裁切以保持紧凑；详情不裁切关键内容。图片不是直播，不使用 LIVE 标记。
- 提醒页可打开露台快照，但若图片不是该事件证据，必须注明“当前设备快照，非事件发生时画面”。当前 HTML 为统一示例图，不能作为工具箱变化的真实证据。
- 原型刷新只模拟等待，不更新拍摄时间、不声称获取了新照片。两种尺寸均使用同一张内嵌露台示例图。

### 生产状态

| 状态 | 表现与操作 |
| --- | --- |
| loading | 首次无图显示占位和加载，不显示黑屏假画面 |
| ready | 显示成功解码的快照和 capturedAt |
| refreshing | 保留旧图与旧时间，按钮暂不可重复请求 |
| stale/offline | 保留缓存，明确“历史画面”、拍摄时间和同步中断 |
| empty | 无可用快照，显示文字占位及转手机入口 |
| failed | 保留旧图（如有）并提示失败；无图则错误占位，可手动重试 |
| forbidden | 清除无权访问的图片，不继续显示旧家庭缓存 |

不要将“同步成功时间”当作“画面拍摄时间”。超过有效时限时标为历史，即使手机可达。有效时限由产品/设备团队配置并联调冻结。

### 模型及建议接口

扩展 Snapshot.thumbnail：imageId、deviceId、capturedAt、receivedAt、width、height、mimeType、byteSize、revision、origin、expiresAt；关联事件另加 eventId/evidenceId。字段缺失不能默认实时。

- GET /api/v1/devices/{id}/thumbnail：返回最新缩略图元数据及短效授权下载地址；没有图时返回明确空状态。
- POST /api/v1/devices/{id}/thumbnail-refresh：提出刷新请求，返回 requestId/jobId；通过既有 jobs 接口查询结果。不保证 SDK 支持主动抓帧；不支持时明确返回 capability unavailable。
- 后端只能从授权设备和受支持 SDK 路径获取帧，不接受任意外部图片地址。主动刷新不得隐式开启录音或长期直播。
- 时间更新条件：服务端确实拿到更新的源图。重复帧、失败、缓存命中不得伪造新的 capturedAt。

### iPhone 到手表的传输与缓存

1. iPhone 获取缩略图元数据，下载并校验大小、类型、解码结果。
2. 缩略图建议长边 400px、JPEG、目标不超过 100KB，作为初始性能预算，真机测试后调整；不得转发全尺寸摄像头帧。
3. WCSession 的状态快照只传元数据；图片采用 transferFile，文件 metadata 带 deviceId/imageId/revision/capturedAt。不要把 Base64 图片塞进 updateApplicationContext。
4. 手表接收文件时及时复制到 App 缓存目录，成功解码且版本匹配后原子替换；旧文件晚到不能覆盖新图。
5. 缓存按账号/家庭/设备分区，首期每设备只保留最近一张。退出登录、权限撤销、切换家庭删除对应图片。
6. 手动刷新沿 commandId 通道提出请求；实际收图后才结束“请求中”。增加超时，失败恢复按钮，不能无限转圈。
7. 首期仅手动刷新与打开页面时按需刷新，不持续轮询或视频流。节流建议每设备 30 秒一次，最终阈值与功耗由团队实测。
8. 网络不可达时只读缓存；手动重试不显示成功。Always-On/锁定状态默认隐藏家庭画面或使用隐私占位，需用户明确设置后才展示敏感内容。
